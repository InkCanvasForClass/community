# 白板界面失去交互与书写停顿

报告现象：白板工具栏对触屏、鼠标均无反应，快捷键失效，但抬手后笔迹仍保留；另有两次约 2 秒停顿。故障机器日志当前不可访问，以下为已验证的代码缺陷和对应修复，不能据此认定每次现场故障都是同一原因。

## 工具栏与快捷键

旧书写路径在按下/移动时将浮动栏和整块白板工具栏设为不可命中，主要依赖抬起事件恢复。丢失抬起或混合输入路径接管时，这个状态可以残留。WinRT 输入区域又忽略不可命中的工具栏，导致这些位置被纳入原生画布。现在书写状态不再关闭整块工具栏命中；原生输入区域和点击分类均按可见的工具栏几何保留 UI 空间，禁用控件不会变成可书写画布。墨迹回放原有的禁用行为保留。

原生输入接管时，旧 WPF 采集、捕获和编辑模式切换不再重复执行。鼠标、手写笔和单个触点的捕获丢失会取消对应的未完成预览；窗口失活也释放遗留鼠标捕获。普通抬起只释放当前触点，避免把其他手指的捕获丢失误认为取消。

原生墨迹窗口不自动激活主窗口。用户明确在白板落笔后，UI 线程恢复白板键盘焦点，避免快捷键仍发往旧弹窗或别的窗口。桌面批注不强制抢焦点。快捷键上下文恢复也只按内置快捷键是否存在判断，插件保留的注册不会阻止内置快捷键重新注册。

原生穿透区域的布局更新改为后台优先级、50ms 合并，避免每次 LayoutUpdated 都在高于输入的优先级重建区域。
未使用漫游或暂停拉直时，不再为每帧触点移动排入只会立即返回的 UI 回调，避免原生输入流持续挤占工具栏和键盘输入。

## 约 2 秒停顿

默认自动保存每 5 分钟触发。虽然磁盘和 ZIP 写入已在后台，旧逻辑仍在 UI 线程遍历所有页面并执行 `StrokeCollection.Save` 的 ISF 压缩。大文档会占用 UI 线程；这是一个可导致停顿的确定路径，但没有现场时间线，不能断言它就是那两次停顿的原因。

现在 UI 只捕获深拷贝、元数据和需要的冻结图像，ISF 压缩移到工作线程。保存期间新增、擦除或切页不会改变已捕获的快照，后台保存失败仍释放保存互斥门。

## 后续诊断

默认轻量响应监测最多只排队一个输入优先级探针；750ms 未响应时记录 `[UIStall] pending`，恢复后记录 `recovered`。日志包含当前 UI 操作及 GC 信息，不自动重启程序或丢弃墨迹。收笔处理、WinRT 转干和保存快照捕获另外记录超过 250ms 的 `[UIWork]`。

若故障机器再次复发，日志中的 `operation=stroke-postprocess`、`winrt-dry-commit`、`save-snapshot-capture` 或 `idle/input-dispatch` 可用于区分收笔计算、转干、快照及调度/其他操作。缺少现场日志时，仍不能排除驱动、GPU 或其他扩展代码的阻塞。

回归覆盖实际 WPF 视觉树中祖先禁用后的工具栏保留区域、隐藏/脱离视觉树的控件、后台快照与并发编辑隔离、UI 真正阻塞时的有界探测和恢复记录。仍需故障设备的双触屏复制显示环境验收。
